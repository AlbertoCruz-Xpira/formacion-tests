Jasmine 1. Primer contacto

Jasmine aparece cuando los asserts básicos se quedan cortos para explicar mejor qué estamos probando. No sustituye la idea de comprobar resultados: la organiza en un lenguaje más legible.

De console.assert a Jasmine

Con console.assert ya podíamos comprobar condiciones sencillas, pero cuando los ejemplos crecen necesitamos una forma más clara de decir qué módulo probamos, qué caso cubrimos y qué esperamos.

Antes: assert suelto

basic-assert.example.js

function sum(a, b) {
	return a + b;
}

console.assert(sum(2, 2) === 4, '2 + 2 debería ser 4');

Qué falta aquí: vemos la comprobación, pero no hay una estructura clara para agrupar casos.

Después: spec con Jasmine

sum.spec.js

describe('sum', () => {
	it('debería devolver 4 al sumar 2 y 2', () => {
		expect(sum(2, 2)).toBe(4);
	});
});

Qué ganamos: el test ya cuenta una historia y deja más claro el comportamiento esperado.

Jasmine es una librería independiente

No forma parte de JavaScript

console.assert existe en el entorno de ejecución, pero Jasmine es una librería aparte que añadimos para escribir tests con más estructura.

Define funciones globales

Al cargar Jasmine, aparecen funciones globales como describe, it y expect.

Su objetivo

No cambia lo que significa testear: simplemente ofrece un lenguaje mejor para organizar y leer las pruebas.

DSL y enfoque BDD

¿Qué es un DSL?

Jasmine propone un DSL (Domain Specific Language) para que los tests se lean casi como frases.

Idea principal: el test no solo ejecuta código; también comunica intención.

¿Y el BDD?

BDD significa Behavior Driven Development. Aquí nos interesa la parte práctica: describir el comportamiento esperado de forma clara.

Palabra Qué expresa
describe De qué unidad o tema estamos hablando
it Qué comportamiento debería ocurrir
expect Qué resultado esperamos observar

Las tres piezas básicas

describe

Agrupa tests relacionados. Suele nombrar una función, un componente o una regla.

it

Define un caso concreto. Lo normal es que se lea como una expectativa breve.

expect

Es la aserción. Compara el resultado real con el que esperamos obtener.

Tests básicos de ejemplo

En esta primera página basta con entender la estructura. Los ejemplos son sencillos a propósito para que se vea el lenguaje de Jasmine sin ruido extra.

Ejemplo 1. Una suma

sum-basic.spec.js

describe('sum', () => {
	it('debería sumar dos números', () => {
		expect(sum(3, 2)).toBe(5);
	});
});

Ejemplo 2. Una decisión simple

access-basic.spec.js

describe('canEnter', () => {
	it('debería permitir el acceso si la edad es 18 o más', () => {
		expect(canEnter(20)).toBe(true);
	});
});

Idea con la que quedarte

Jasmine no cambia el objetivo del test. Lo hace más claro, más agrupado y más legible que un conjunto de asserts sueltos.
