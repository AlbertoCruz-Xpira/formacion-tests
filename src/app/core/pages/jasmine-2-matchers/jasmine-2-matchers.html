Jasmine 2. Matchers

En esta página nos centramos en los matchers, que son la parte de Jasmine que expresa qué resultado esperamos. Aquí verás solo casos básicos y muy prácticos.

Qué es un matcher

Un matcher es la pieza que acompaña a expect(...) para comparar el valor real con el esperado. En otras palabras: traduce la expectativa del test a una comprobación concreta.

Estructura base

expect(valorReal).matcher(valorEsperado)

Propósito

Hacer el test más legible y explicar claramente qué se está validando.

Resultado

Si el matcher no se cumple, Jasmine marca el test como fallido.

Matchers básicos más usados

Matcher Cuándo usarlo Ejemplo corto
toBe Comparar valores primitivos exactamente expect(total).toBe(3)
toEqual Comparar objetos o arrays por contenido expect(user).toEqual({ id: 1 })
toContain Verificar si un array o texto contiene un valor expect(tags).toContain('ui')
toBeTrue / toBeFalse Comprobar booleanos explícitos expect(isValid).toBeTrue()
toBeGreaterThan Comparar rangos numéricos expect(score).toBeGreaterThan(0)

Operadores de JS vs Matchers de Jasmine

Los operadores de JavaScript (== y ===) comparan valores, pero no forman parte del sistema de reporting de Jasmine. Los matchers sí están integrados en expect(...) y generan mensajes más claros cuando algo falla.

Operadores JS

=== compara de forma estricta y == compara con coerción. Sirven para lógica normal de código, pero no reportan fallos como Jasmine.

Matchers en Jasmine

Se usan dentro de expect y aportan contexto: qué esperabas y qué llegó realmente.

Regla práctica

En tests, prioriza matchers. Son más legibles y mejores para diagnosticar errores.

Matcher Comparación JS parecida Cuándo usarlo Ejemplo
toBe === Primitivos o igualdad estricta expect(5).toBe(5)
toEqual Comparación de contenido Objetos y arrays expect({ a: 1 }).toEqual({ a: 1 })

Ejemplos básicos con Jasmine

1. toBe y toEqual

toBe-toEqual.spec.js

describe('price summary', () => {
  it('debería calcular el total', () => {
    const total = 2 + 3;
    expect(total).toBe(5);
  });

  it('debería devolver un objeto esperado', () => {
    const summary = { items: 2, total: 5 };
    expect(summary).toEqual({ items: 2, total: 5 });
  });
});

2. toContain y toBeTrue

contain-boolean.spec.js

describe('user tags', () => {
  it('debería contener el tag premium', () => {
    const tags = ['new', 'premium', 'active'];
    expect(tags).toContain('premium');
  });

  it('debería marcar al usuario como activo', () => {
    const isActive = true;
    expect(isActive).toBeTrue();
  });
});

3. toBeGreaterThan y not

numeric-not.spec.js

describe('score rules', () => {
  it('debería ser mayor que cero', () => {
    const score = 7;
    expect(score).toBeGreaterThan(0);
  });

  it('no debería ser negativo', () => {
    const score = 7;
    expect(score).not.toBeLessThan(0);
  });
});

4. Ejemplo corto y realista

email-validator.spec.js

function isValidEmail(value) {
  return value.includes('@');
}

describe('isValidEmail', () => {
  it('debería aceptar un email válido', () => {
    expect(isValidEmail('ana@mail.com')).toBeTrue();
  });

  it('debería rechazar un texto sin arroba', () => {
    expect(isValidEmail('ana.mail.com')).toBeFalse();
  });
});
