¿Qué es un test unitario?

Un test unitario es una prueba automática que verifica que una pequeña parte del código (normalmente una función o método) funciona como se espera, de forma aislada del resto del sistema.

Definición básica

Un test unitario comprueba el comportamiento de la unidad más pequeña de código que tiene sentido por sí misma, como una función, método, clase o procedimiento.

Su objetivo es confirmar que, para unas entradas dadas, esa unidad devuelve las salidas correctas o realiza los efectos esperados.

Cómo se escribe

Se suele seguir el patrón Arrange-Act-Assert: preparar datos y entorno, ejecutar la función y hacer aserciones sobre el resultado.

Cada test cubre un caso concreto (por ejemplo: caso normal, borde o error), y un conjunto de tests forma la batería de casos de prueba para esa unidad.

Para qué sirve

Detectar errores pronto

Ayuda a detectar errores durante el desarrollo, antes de integrar con otras partes de la aplicación.

Facilitar el refactor

Si los tests siguen pasando después de cambiar el código, existe alta confianza en que el comportamiento se mantiene.

Reducir regresiones

Una buena base de tests unitarios protege reglas clave de negocio y evita romper funcionalidades al evolucionar la aplicación.

Quién los hace y cuándo

Normalmente los escriben los propios desarrolladores mientras implementan o justo después de implementar la funcionalidad.

También son una base importante de prácticas como TDD (desarrollo guiado por pruebas), donde se escribe primero el test y luego el código para hacerlo pasar.
